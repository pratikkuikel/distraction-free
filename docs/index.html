How it works, in plain terms

Most blockers live inside your browser — easy to disable, and useless against apps. This one works differently: it sits at the network level, on your device, and decides whether to let a connection through before it ever reaches an app or browser.

🔒 Always blocked

Adult content, gambling, piracy sites, and known ways to bypass this kind of filter (VPNs/proxies built for evasion). No toggle, no schedule — always on.

🌙 Scheduled

Instagram, TikTok, X, Facebook, Reddit, YouTube, LinkedIn: hard-blocked 8pm–9am every night. Open the rest of the day, with a manual "block it now" switch if you want extra discipline.

💬 Always allowed

WhatsApp, Messenger, Telegram, and Botim are never touched by the schedule — messaging stays messaging, not a distraction.

🔥 Streaks & stats

A day-streak counter, a rough (deliberately conservative) estimate of time/data you didn't spend on blocked sites, and a daily motivational quote — not to be cute, but to make the win visible.

It's honest about its own limits: you have admin/root access to your own device, so nothing here pretends to be unbreakable by you. The "Disable protection" button in the app is a deliberate piece of friction — it logs the attempt and shows a 24-hour countdown that never actually finishes. The only real way off is a manual uninstall, on purpose, outside the app.

How optimized is it?

Battery and memory use were profiled directly, not assumed — a few concrete numbers:

~0%
CPU at idle (macOS filter), measured with powermetrics
0
Android wakelocks held by the app, per batterystats
3
scheduled wakeups/day (nightly toggle ×2, blocklist refresh ×1) — everything else is passive

The filtering itself is a blocking network read that uses effectively zero CPU while idle — cost tracks how much traffic you actually generate, not wall-clock time. A background 5-second UI refresh timer on macOS was found and fixed during profiling (it now only polls while the menu is actually open); on Android, a silent TCP-connection leak on dead peers was found and fixed so the app doesn't slowly degrade over a long uptime. Both fixes shipped once verified, not just assumed.

What you can expect

  • ✅It changes real network settings. macOS: your DNS points at a local resolver. Android: an always-on local VPN (not to any server — just how the OS lets an app filter traffic). That's the mechanism, not a side effect.
  • ⚠️You'll see OS security warnings once. Unsigned by an Apple Developer ID, not on the Play Store — both cost money/accounts this project skips on purpose. The install steps handle this for you.
  • 🚫Nothing phones home. No account, no server, no analytics. The only network calls it makes on its own are fetching public blocklists and resolving DNS.
  • 📊The stats are honest estimates, not measurements. "Time/data saved" is a small, clearly-labeled flat credit per blocked attempt — illustrative, like Brave's own bandwidth-saved counter, not a real measurement.
  • 🐞It's an actively maintained side project, not a polished commercial product. Found a bug? File an issue — there's a built-in diagnostic log you can export and attach.
